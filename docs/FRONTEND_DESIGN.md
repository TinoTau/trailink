# Trailink V1 前端设计说明

版本：V1 MVP 第一阶段  
日期：2026-10-23  
状态：当前界面基线

本文档说明本阶段订单与行程界面，不引入复杂日历组件或路线编辑器。

---

## 1. 页面与路由

| 路由 | 页面 | 说明 |
|------|------|------|
| `/login` | 登录 / 注册 | 司导或公司注册，调度员由批准产生 |
| `/driver/calendar` | 我的行程 | 登录用户本人的行程日历；公司、调度员、司导都能跑单 |
| `/dispatcher` | 调度台 | 公司、调度员 |
| `/company/assign` | 派给调度 | 仅公司。复用调度台页面，右侧是本公司调度员，只整单分配 |
| `/company` | 公司信息 | 独立白底页，分块同个人信息。下拉显示本人公司简称。公司资料一块放二维码、公司全名、联系方式、公司简称和负责人；待批准申请、调度员、订单各自一块。调度员姓名后是该用户自己填写的联系方式。订单为圆角图标，点击后出卡片 |
| `/me` | 个人信息 | 独立白底页。资料（头像、姓名、联系方式）和登录信息（用户名、密码）分成两块，申请另成一块；可改自己的姓名、登录用户名和登录密码，上传头像；可搜索调度员申请成为司导；调度员可批准申请人；司导/调度员也可搜索公司申请成为调度员 |

路由、菜单和角色准入只在 `frontend/src/navigation.ts` 定义。API transport types 从后端 OpenAPI 生成到 `frontend/src/api/generated/`；`types.ts` 不再手写一套后端 DTO，只保留别名、响应归一化和纯 UI 模型。

公司登录后进入调度台，不经过订单列表顶栏。公司信息、个人信息与调度台、司导日历一样是独立白底页。右上角「我的行程」单独成按钮；旁边用三点图标展开下拉（派给调度仅公司可见、调度台、公司信息、个人信息、退出）。当前页不出现在列表里，司导看不到调度台，已在行程页时不再重复「我的行程」。页面操作（行程管理、创建订单）仍留在外面。不使用 Ant Design 顶栏。不另建平行订单详情页。公司与调度员也走同一套「我的行程」，不另做调度员日历。

---

## 2. 订单入口

订单不再单独提供 `/orders` 表格页或 `/orders/:orderId` 编辑页。进行中的单在调度台，历史单在公司信息，本人行程在 `/driver/calendar`。旧地址重定向到角色首页。行程天数取接口返回的 `dayCount`。

---

## 3. 订单编辑 / 详情

调度台订单卡片与司导点日期展开的明细共用 `OrderInfoFields`，保存走 `updateOrderInfo` → `PUT /api/orders/{id}`。调度台可改公司订单号和自己的调度备注；我的行程只改司导备注和截图，不能改公司订单号。点开某一天时，公司订单号下面显示当天调度员的姓名和联系方式。订单图标、卡片头、公司信息订单图标和卡片、领取成功提示、取消行程和冲突提示都不展示系统订单号：有公司订单号用公司订单号，否则用各自备注，都没有就空着，超过 12 字截断。领取框只提示输入公司订单号。调度台只读写当前调度员自己的调度备注 `notes`（`order_notes`，互不可见），我的行程只读写司导备注 `driverNotes`。调度员在订单信息里搜索并点选公司后，立即用 `PUT /api/orders/{id}` 写入 `companyId`，不必再点保存；公司账户只看到绑到本公司的单，所属公司只读。点某一天的活动仍是同一套 `DriverDayEditor`。

### 3.2 行程日期缩略卡片

按日期连续排列小卡片，每张显示：

- 日期
- 结束地点
- 司机
- 活动项目数量

点击卡片选中该日。支持新增行程日、删除行程日、整单派司机。

### 3.3 当日行程

选中日期后展示并可直接编辑：

- 当日行程描述
- 结束地点
- 当日司机（按天派单）
- 活动项目列表
- 电子票上传（写入 `ticket_path`，可查看）

活动项目可新增、修改、删除、拖动排序。字段：活动内容、承办方、预订时间、签到时间、电子票文件、展示顺序。订单截图在调度台订单卡和公司信息历史卡上传。

日期提交 `YYYY-MM-DD`。预订/签到时间提交 `YYYY-MM-DDTHH:mm:ss`，禁止使用 `toISOString()` 或带时区偏移的字符串。

不实现实际签到打卡。四种上传共用 `AppFileStore`。

## 4. 交互约定

- 整单派单调用 `PUT /api/orders/{orderId}/driver`。
- 公司把整单交给调度员调用 `PUT /api/orders/{orderId}/dispatcher`，不拆天。
- 按天派单通过更新当日行程的 `driverId`。
- 订单详情一次拉取主体、行程和活动，不再逐条请求活动。
- 调度台与行程日历是白底独立页，不引入第三方日历或地图。
- 文案使用简体中文。

---

## 5. 司机端日历

独立页面，不使用调度端顶栏。

- 白底独立页，标题为「我的行程」。月份上下连续滚动，默认停在当前月并尽量露出今天。当天用浅灰细边框标出，不另加色块或加粗数字。
- 七列周一至周日；有行程日期用圆角药丸格填充，空白日期只显示数字。有行程的日期框与调度台司导日历共用 `CalendarDayCaption`。调度台数字下显示分配人姓名（优先 `assignedByName`，否则 `createdByName`）。我的行程在此基础上加上订单所属公司：公司名和调度员名连写，超过 6 个字且本人在公司信息里写了缩写时，改成「缩写-调度员名」。
- 已完成 / 未完成颜色可分别选择，默认薄荷绿 / 浅蓝，保存在 `localStorage`。月份标题旁不重复图例，只保留页面右下角两个按钮。
- 点击有行程日期在当月日历下方展开圆角卡片：卡片头与调度台订单卡同一套 `OrderInfoPanel`——订单号旁笔记按钮打开编辑，备注显示在订单号之下、日期之上；收起后只留备注预览。编辑内容为司导备注和订单截图，不能改公司订单号。下面再展示已添加活动和一套「添加活动」。司导备注与调度台调度备注分开。同一天有空行程时不另画添加按钮。活动可拖动排序，顺序写入 `sort_order`。再点同一天收起卡片。
- 登录后日历只显示本人 `driver_id` 的日期，已结束的单也留在对应日期上，用「已完成」色。公司、调度员注册或登录时若还没有司机身份，会补一条 `drivers` 记录，方便自己跑单。页面数据只读 `GET /api/orders`：司导在服务端按 `driver_id` 过滤，前端再按登录 `driverId` 画格子；不再拉司导列表或切换他人。不另开调度员日历。
- 右上角为「行程管理」：下拉可输入订单号领取已有订单（`PUT /api/orders/{orderId}/driver`；已绑公司的真实订单领取时覆盖并删除本人未绑公司占位单；已分给调度员的单领取后分配人记为该调度员，调度台可解除绑定；领取成功后日历跳到该单首日并展开当日卡片），或在日历上拖选起止日期后走共用的 `createOrderWithDays`（内部仍是 `POST /api/orders` 与 `POST /api/orders/{orderId}/days`，并写当前司导 `driverId`，不写 `companyId`）；也可点「取消行程」后点击某天，只解除当前司导在该单上的日期（`PUT` 当日 `driverId: null`），其他司导的日期不受影响。点开某一天后，备注图标右侧垃圾桶先把这一天套上红框，再点一次该日期才解除当天这一条，与取消整单同一套红框确认，不弹框，走同一套 `PUT`。其余日期仍留在本人名下，订单成为拆单，调度台未分配重新列出。取消在有效点击或键盘 Enter / Space 后触发，滑动日历不解除绑定。框选添加仍用按住拖选；行程管理面板预先留出确认按钮高度，拖选时不因按钮出现而挤走日历。前端不封装 `claim` / `range` 客户端。
- 颜色选择由底部「已完成」「未完成」打开。不把前端 `driverId` 当作登录身份。
- 电子票上传后可打开查看；文件走统一本地存储。

## 6. 调度台

独立页面，不使用订单列表顶栏。风格与司机日历一致：白底、圆角大图标、底部色点改色。

- 调度台左上角是当前登录用户姓名；派给调度左上角是本公司名称。都读登录身份，不再本机改名。
- 上半区订单、下半区司导。司导图标只来自已向当前调度员申请并批准的人；公司打开同一页时只看到本公司司导。公司账户或该公司调度员派发公司订单后，这位有账号的司导成为本公司司导，出现在公司这份名单里。公司「派给调度」的图标只来自已向本公司申请并批准的调度员。姓名搜索只在个人信息页用来提交申请，不会把人放进这些名单。订单区按钮顺序为「创建订单」「未分配订单」「所有订单」；「已分配颜色」只在选中「所有订单」时出现。颜色读当前用户 `assignedColor`，点选走 `PUT /api/auth/assigned-color`，每人一条，不写本机。
- 未完成按结束日期尚未早于今天；进行中订单排最前，再按出发日期靠近今天排序。
- 点击订单图标，在订单区域弹出覆盖该区的日历卡片；点击司导图标，在司导区域弹出覆盖该区的未来行程卡片，姓名下显示该司导自己填写的联系方式。该司导名下所有派出单的日期都画出来；自己分配的日期显示本人姓名，可拖回订单区取消；其他人分配的日期只着色不写名字，不能移除，不再显示订单号后四位。分配人看行程日 `assignedByUserId`，旧数据回退订单 `createdByUserId`。两卡同时打开时，滑动订单日历会按月份带动司导日历，滑动司导日历不带动订单日历。司导卡会画出当前打开订单覆盖的月份，即使该司导当月没有行程。订单、司导、创建订单日历里当天都用与司机日历相同的浅灰细边框标出。订单卡片与司导日期卡共用 `OrderInfoPanel`：名字旁笔记图标打开编辑，备注显示在订单号之下、日期信息之上。可改所属公司（调度员搜索公司名称，点选后立即绑定或改绑）、平台订单号和自己的调度备注，并上传订单截图。订单号和备注点保存走现有 `PUT /api/orders/{id}`，保存后回到日历。公司账户看所属公司只读。调度备注各人各写各的，司导看不到。删除按钮是简笔垃圾桶，在编辑按钮右侧，样式和间距与司导卡移除一致。备注图标为蓝色。已绑公司时调度员按钮为「退回公司」，确认后走同一 `DELETE /api/orders/{id}` 只解绑并退回公司池；未绑公司时调度员也是「删除订单」，确认后真正删掉。公司账户始终是「删除订单」。点击某一天打开独立的当日行程卡片（同一套 `DriverDayEditor`），不和订单信息编辑叠在同一张卡里。司导卡片备注仍是名字右侧蓝色简笔图标。图标网格保持原位，不另占下方空间。
- 拖动订单卡片或未分配订单图标到司导图标；若司导卡片已打开，拖到司导区域即整单分配。调用现有 `PUT /api/orders/{orderId}/driver` 且 `failOnConflict: true`。日期冲突返回 409，不写入，不关闭卡片。已绑定公司的真实订单覆盖司导自建占位单时不报冲突，占位单由后端删除。未绑定公司的调度员自建单仍走冲突。
- 拖动订单或司导日历里的某一天到司导，调用现有 `PUT /api/orders/{orderId}/days/{dayId}` 且 `failOnConflict: true`，只改该日 `driverId`。不新建订单。
- 从司导日历把某一天拖到订单区域：仅自己分配的日期可拖；其他人分配的日期不能拖走。若该单是拆单，只把当天 `driverId` 置空；若该日未拆单（整单都是这位司导且同一人派出），调用 `PUT /api/orders/{orderId}/driver` 清空整单。不关闭卡片。拆单判定与当日编辑器共用 `isSplitOrder`：多个司导、多个分配人，或已派天数小于行程天数。我的行程取消本人 `driver_id` 名下日期，不看出是谁派的。
- 未分配订单包含尚未派完的单：全部未派，或拆单后仍有空日期，不论结束日是否已过。全部日期都已派的不出现在未分配。
- 「所有订单」列出有行程日、且尚未成为历史单的订单。已派完且结束日早于今天的单不出现。整单已派用本机保存的背景色。拆单或只派了部分日期时，图标本体保持白底，右上角用直线切开一块已分配色，不按天数比例给整块上色。订单日历里已派日期与未派日期仍用这两种颜色。改色方式与司机日历「已完成 / 未完成」相同。部分日期已派时显示「拆分」。
- 「创建订单」打开覆盖订单区的日历卡片，操作与司导「行程管理」框选建单相同：按住拖选起止日期后确认，确认按钮在卡片右下角。走同一套 `createOrderWithDays`，不写 `driverId`，也不默认写 `companyId`；新单出现在未分配，所属公司须事后搜索绑定。一次最多 31 天。不另建创建接口或页面。
- 司导图标头像下方优先显示当前调度员自己给该司导写的备注（`driver_notes`，接口仍用 `notes`），没有备注才显示姓名；超过 12 字截断，与订单图标同一套截断。其他人写的备注看不到。卡片标题、恢复隐藏仍用姓名。司导置顶是图标右上角简笔按钮；移除在司导卡片里、备注按钮右侧并留间距，避免误触。可拖动同组排序。未置顶且未手动排序的按姓名排序。布局只存在 `localStorage`。

## 6b. 派给调度

公司账户菜单「派给调度」打开 `/company/assign`，复用同一套 `DispatcherPage`，不复制订单页。右侧图标是本公司调度员（`GET /api/company` 的 `dispatchers`），不是司导。未分配是还没有 `assignedDispatcherUserId` 的本公司订单。拖订单或拖某一天到调度员都走 `PUT /api/orders/{id}/dispatcher`，整单覆盖；从调度员订单池拖回订单区则整单收回：清空调度员，并清空各行程日司导。同一时间只能分给一位调度员。再分给调度员后从没有司导开始。点击调度员打开订单池，不是日历；「未完成订单 / 已完成订单」切换该调度员接手的本公司单。池里图标第一行是当前公司自己的备注，没有则公司订单号，都没有就空着；第二行日期，第三行天数。颜色表示有没有派给司导，不写「已分配」。点击订单打开日历，日期按有没有司导着色，格子上标司导姓。公司订单备注走 `order_notes` 本公司账户那一行，调度员和司导看不到。公司给调度员的备注走 `dispatcher_notes`，头像下方优先显示备注，调度员自己看不到；点开订单池时名字旁笔记可改。调度员只能排序或置顶，不能隐藏。调度员默认只在调度台看到分给自己的单；调度员自己建的单自动记在自己名下。

## 7. 登录与角色

未登录进入 `/login`。公司账户能打开全部页面，登录后进入调度台。仅公司能打开「派给调度」。调度员打开调度台、我的行程、公司信息和个人信息。司导打开行程日历、公司信息和个人信息。公司与调度员也能进「我的行程」跑自己的单。公司信息页用下拉切换。下拉里是所属公司以及自己接过订单的公司，选项文字是本人编辑的公司简称。页内公司名称显示全名，公司账户可在输入框里修改并保存，另有负责人、联系方式（持有者可改手机/微信并上传二维码）。公司简称输入框前标「公司简称」（和其他用户建立联系时默认用公司账户已保存的简称，没有则用公司名前两个字，最多 20 字，`PUT /api/company/notes`），还有订单图标。批准申请和调度员名单只给公司账户看；调度员和司导看不到这两项。公司账户只看本公司已派完且已结束的历史单。司导看自己当前接的单，调度员看自己当前接的和自己当前分配的单；已结束和尚未结束的都在内。分配一变，这张单就不再出现。点图标打开弹框，点弹框外关闭。图标三行是公司订单号或备注、起始日期、天数。弹框里每个日期后面先是当天活动，活动框留白，多个活动用 `-` 连接，活动后再显示当天司导，没派司导时写未分配，活动过长只显示开头。弹框不再另写一行公司订单号。公司、调度员、司导改的是同一条 `order_activities.content`。弹框里也可上传订单截图。个人信息页可改自己的姓名、联系方式、登录用户名和登录密码，上传头像，服务端压缩后再展示。改名后调度台司导卡与本人行程用同一姓名，不再留旧的 `drivers.name`。公司信息页在桌面数据返回前显示「加载中…」，不先闪「还没有加入公司」。也可搜索调度员申请成为司导；调度员在同一页批准。公司账户在公司信息页批准或移除调度员，名单里姓名后面是该用户自己填写的联系方式。

## 8. 本阶段不做

- 独立的调度员日历（与「我的行程」共用）
- 路线编辑器
- 复杂状态标签
- 权限矩阵、微信登录、按公司隔离订单
