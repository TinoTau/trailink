# 调度员在「我的行程」看不到别人派给自己的行程

## 现象

用陈调度（调度员账号，也有司导身份）验证抢单时，「我的行程」里看不到自己的行程。

## 原因

「我的行程」请求 `GET /api/orders` 时不带条件，后端按账号角色决定返回什么：司导账号返回行程日派给自己的单，调度员账号返回自己负责派单的单（`assignedDispatcherUserId`）。所以别的调度员派给陈调度司导身份的行程（包括抢单后被确认的）都拿不到，只有自己派给自己的单能看到。这段逻辑早就如此，有了抢单后调度员也会被别人派单，问题才暴露。

## 改动

- 后端 `GET /api/orders` 加参数 `mine=true`：只按当前账号自己的司导身份取行程，不看角色；没有司导身份返回空。
- 前端「我的行程」改用 `ordersApi.list({ mine: true })`；调度台的查询不变。
- 重新生成前端接口类型；API_CONTRACT 订单列表一节补 `mine`。
- 新测试 `My_trips_show_days_other_dispatchers_gave_a_dispatcher_as_driver`：王调度派给陈调度的单出现在陈的 `mine` 里，陈自己派给别人的单不出现；调度台照旧；没有司导身份的公司账户为空。改代码前这个测试失败，改后通过。

## 验证

- `dotnet test`：124/124 通过。
- 前端 `tsc -b`、`npm run build` 通过。
- 沙盒界面：陈调度（手机宽度）打开「我的行程」，王调度派给他的那天显示「皇 6 公司-王调度」。
