# Code review 与打包 2026-11-09 发布

## Code review

范围：上次线上版本（2026-11-03）以来的全部改动。后端对着服务器上那版源码包逐个文件比较；前端看 11-08 那次 review 之后的改动（拖动改日期、点日期先开司导、日历对齐）。

### 后端

- 没有新的迁移，数据库结构和 20261102b 一样。
- `PUT /api/orders/{id}/dates`（`OrderReschedule`）：
  - 权限：所属公司、负责的调度员；自留单是建单人。
  - 范围最多 93 天，一次最多挪两年。
  - 平移在一个事务里分两步写（先挪到临时日期再放到新日期），避开同单同日的唯一索引。
  - 电子票文件在写库成功后才删。
  - 活动时间是不带时区的本地时间，平移整天没有夏令时偏差。
  - 冲突：司导那天有别的行程就改回未派；车辆被占就去掉车辆。
  - 待确认的抢单不按日期记录，确认时会重新检查冲突，改日期后不会派出冲突的日子。
  - 没发现问题。
- 删除 / 退回按界面区分（`release`）：
  - 退回时 `ReturnToCompanyPool` 把等级改回自留、清掉派单人，所以公司账户调度台的「旧单」规则不会把退回的单又算回调度台。
  - 待确认的抢单一并删除。
- `OnDesk` / `IsOnDesk` 两处规则一致；抢单待确认列表、司导行程详情范围都用它。

### 前端

- 改日期：
  - 换订单就退出改日期；
  - 要删掉日子时「保存」两步，点日历重新拖会撤掉红框；
  - 改日期中点日期不会进当日行程、不会派单。
- 本轮改了一处：`alignCalendarScroll` 在滚动时频繁调用，原来每次从头遍历所有日期格子找顶上第一个看得见的日期，改成只在顶上这个月和下一个月里找。结果不变，对齐测试复跑一致。
- lint 没有错误，只有原来就有的提示类警告。

### 记下来、这次不改

- 调度台上把公司的单退回公司订单池时，已经过去的日子的司导也会一起清掉。这是以前调度员删除就有的行为。要保留历史日子的派单，需要单独改。
- `selectOrderDay` 依据的是当前打开的司导；车辆视图下的点日期行为没变。
- iPhone Safari 仍建议用真机过一遍拖动改日期和长按。
