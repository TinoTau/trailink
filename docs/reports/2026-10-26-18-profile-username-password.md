# 个人信息可改登录用户名和密码

## 目标

每个已登录用户在个人信息页改自己的登录用户名和登录密码。仍写现有 `users.username` 和 `users.password_hash`，不新建账号表或平行接口。

## 改动

- `PUT /api/auth/username`：3 到 50 个字符，忽略大小写后不能与其他人重复。改完重新写入登录 Cookie，用户 id 不变，当前会话保持登录。
- `PUT /api/auth/password`：须提交当前密码和新密码。当前密码不对返回 400「当前密码不正确。」，不改哈希。新密码至少 8 位。改完保持登录。
- 个人信息页在姓名下面增加用户名、当前密码、新密码。用户名未改或短于 3 个字符时不能保存。当前密码为空或新密码短于 8 位时不能保存。
- 契约、产品说明、库说明和架构说明已同步。OpenAPI 类型已重新生成。

## 命令结果

- `dotnet test --filter User_can_change_own_username_and_password`：通过 1。覆盖重复用户名、过短用户名、改名后旧用户名不能登录、新用户名可以登录、错误当前密码、过短新密码、改密后旧密码不能登录、新密码可以登录，以及另一账号不被改动。
- `npx tsc -b`：通过。
- 已重启 `http://localhost:5168`，并按该服务的 OpenAPI 重新生成前端类型。
- 浏览器打开已登录公司的个人信息：用户名输入现为 `bbboss`。改成已被占用的 `chen` 后提示「用户名已被使用。」，会话用户名仍是 `bbboss`。当前密码填错后提示「当前密码不正确。」。没有改掉这个账号的用户名或密码。页面上的输入已恢复。
