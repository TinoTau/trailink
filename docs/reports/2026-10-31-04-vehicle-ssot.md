# 车辆管理与订单管理重复逻辑合并

## 目标

车辆管理里和订单管理重复的排序、日期查找、日历跳转、拖回解除绑定，收成同一套方法。不改操作结果。

## 改动

- 行程日按日期查找收成 `dayOnDate` / `ordersOnDate`。司导日期和车辆日期仍用原来的名字，内部转过去。起止日期收成 `dateSpan`，订单跨度继续走它。车辆日历上同一张订单已绑定日期的起止也用它。
- 司导和车辆的置顶、拖动排序走 `toggledPins`、`movedLayout`、`writeBoardLayout`。车辆排序仍先套现有的司导排序。
- 绑定和解除车辆后，订单列表和司导行程用同一个 `patchVehicleDays` 改 `vehicleId`。
- 打开司导并滚到某一天收成 `queueDriverFocus`。拖车辆到未打开的司导、点司导图标、点车辆日历日期、点司导日历日期都走它。行程还没加载时，非今天的日期会先记下来，避免被滚到今天盖掉。
- 从司导日历拖回订单区：车辆管理解除车辆，订单管理解除司导。车辆管理里没拖到订单区仍然直接结束，不会改去派单。
- 车辆日历的标记改用已经合并过的订单列表，不再单独再合一次。点日期找订单也用这份列表。
- 删掉车辆拖拽松手时重复算出来的司导 id。

## 命令结果

- 前端 `tsc -b --noEmit`：通过。
- 浏览器：刷新后调度台仍是 CC-boss。车辆页显示「暂无车辆」。切回订单后「所有订单」仍是 CC-test001、CC-test002、CC-test003。没有点 Mason。没有新建或删除数据。
- 没有重启 API。绑定接口没改，没有重跑车辆测试。

## 未做

- 没有把解除车辆和解除司导并成一次请求。前者清 `vehicleId`，后者清 `driverId`。
- 没有把车辆删除的红框和订单删除确认框并在一起。
- 服务端按司导分单仍在 `ItineraryDaysController`。它和前端的拆单判断对应，但不能跨语言共用。
- 司导图标和车辆图标的 class 名各写了一行。放下的条件不一样，单独建文件不值得。
- 没有在浏览器里重做拖拽、绑定、冲突解除。当前没有车辆，现有三张订单也不是这位调度员分配的。
