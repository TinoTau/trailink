# 抢单改为调度员确认；调度台抢单显示；司导备注保存后回到详情

## 需求

- 放出去的单（公司内部、面向所有人）在调度台用虚线边框，表示随时可能被抢。
- 被抢后要调度员确认：订单图标多一行「抢单待确认」。
- 抢单司导出现在司导区，排在置顶之后、未置顶之前，虚线边框。点抢单司导打开相应订单；点抢单待确认的订单打开相应司导。
- 一张公开单可以被多位司导抢；多人抢时右上角标红（同普通冲突单），点订单弹出和重复日期框类似的选择框，每格写司导名、扑克牌图案做底；司导区跳到这些司导，图标显示同样的扑克牌，点选择框或司导图标查看司导详情。
- 订单卡片（日期天数下方）和司导卡片（司导备注下方）加「确认派单」，确认后绑定、从抢单页移除、等级改回调度自留。
- 小问题：调度员编辑司导备注保存后应回到司导详情。

## 改动

### 数据库

- 迁移 `AddOrderClaims`：新表 `order_claims`（订单、抢单人、司导身份、抢单时的等级、时间；同一人同一单唯一）。只新增，开始是空的。
- 结构脚本 `trailink-schema-20261102b.sql`（含 `AddOrderShareLevel` 和 `AddOrderClaims`，可重复执行）和 `apply-schema-20261102b.sh`。

### 后端

- `OrderGrab` 改为两步：
  - 司导 `POST /api/grab/{id}` 只写抢单记录，不派单；`DELETE` 撤回；列表带 `claimedByMe`。
  - 调度员 / 公司 `GET /api/grab/claims` 看待确认的抢单；`POST /api/grab/{id}/confirm` 确认：再查一次冲突，派未派日期（派出人是这张单的调度员），按抢单时的等级建立关系，删掉这张单所有抢单，等级改回调度自留。
  - 被拉黑的司导不能抢，已抢的也不列给调度员。
- `DriverRoster.Viewable`：抢自己订单的司导即使还不在名单里，也能看他的资料、头像、驾照、日历，也能写备注、隐藏。名单接口不变。
- 读取列表时按内存里的日期再判断一次，避免分批读取时日期刚好被派走导致报错（测试里偶发 500 的原因）。

### 前端

- 调度台订单图标：虚线框（`shared`）；第四行「抢单待确认 / N 人抢单待确认」；多人抢右上角红角。
- 司导区：抢单司导（含陌生人）排在置顶之后，虚线框；当前订单多人抢时图标换成扑克牌。
- 点订单 / 点抢单司导的联动；多人抢的选择框（`ClaimParts.tsx` 的 `ClaimPickPopover`）。
- 订单卡片、司导卡片的确认条（`ClaimConfirmBar`，经 `DispatcherCalendarCard` 的 `action`）。
- 抢单页文案改为「抢」；已抢的单橙色虚线框、「已抢单，等调度员确认」和「撤回」；顶部提示已抢几张。
- 司导备注：点「保存」成功后收起编辑回到详情。失焦自动保存和点保存几乎同时触发时，后者等前者结果（原来第二次会被锁挡住，导致不收起）。

## 补充：调度自留不出现在抢单页

用户说明：调度自留是调度员留着分给熟悉司导的单，不应该在抢单页展示。

- 抢单页只列公司内部、面向所有人的单；调度自留的单谁都看不到，直接调接口抢也返回 404。原来自留单会给调度员自己的司导看。
- 已经有人抢的单如果被改回调度自留，调度员仍能在调度台确认已有的抢单，但不会有新的人能抢。
- 抢单页筛选只剩「全部 / 公司内部 / 面向所有人」，说明文字同步修改。
- `GrabTests` 改为：自留单对自己的司导、公司的司导、陌生人、调度员都不出现，抢单 404。后端 107 / 107 通过。
