# 保存按钮统一放在关闭按钮左边 2026-11-10

## 需求

保存按钮应该在关闭按钮左边。检查所有创建或更新的地方，保存按钮的位置对不对。

## 检查结果（改前）

| 位置 | 原来 | 现在 |
|---|---|---|
| 调度台编辑订单 | 卡片里「订单信息」标题旁 | 卡片头，关闭 × 左边 |
| 司导卡片备注、当日卡片备注 | 卡片里「备注」标题旁 | 卡片头，× 左边 |
| 车辆卡（添加 / 编辑车辆） | 卡片里单独一行 | 卡片头，× 左边 |
| 我的行程里的订单信息 | 卡片里标题旁 | 卡片头右上角 |
| 公司信息订单弹框 | 弹框里「订单信息」旁 | 弹框头，「关闭」左边 |
| 创建订单 | 底部「添加 x–y 仅日期」 | 头上「添加」，× 左边；底部写已选日期 |
| 改日期（调度台、公司信息弹框） | 底部「取消 / 还原 / 保存」 | 头上「保存」，× 左边；底部说明和取消 / 还原 |
| AI 建单 | 底部「生成订单（n 天）」 | 头上，× 左边；底部「重新上传」 |
| 活动库：添加 / 编辑活动 | 底部 | 头上，「关闭」左边；删除活动留在底部 |
| 活动库：活动评价 | 表单中间 | 头上「保存评价」，「关闭」左边；删除我的评价留在原处 |
| 活动库：选活动 | 底部「添加 n 项」 | 头上，「取消」左边；「手动填写」留在底部 |
| 个人信息、公司资料的行内保存 | 输入框后面 | 不变（没有关闭按钮） |
| 当日行程里活动的「保存 / 取消」 | 保存在取消左边 | 不变 |

## 改动（只改前端）

- `OrderInfoFields.tsx`：
  - 新增 `SaveSlotContext` 和 `SaveSlot`。卡片头在关闭按钮左边留一个空位（`card-save-slot`，`display: contents`），编辑区的「保存」用 portal 画进去；不在卡片里时照旧画在标题行。
  - `OrderInfoPanel` 头右边改成 `card-head-actions`（空位 + 关闭），把空位交给自己里面的编辑区，也交给卡片（`onSaveSlot`）。
  - 空位的 ref 回调用稳定的 `useCallback`，避免每次渲染反复设值。
- `DispatcherCalendarCard.tsx`：
  - 订单日历卡、当日卡片都把空位交给卡片内容；
  - 新增 `headAction`：头上 × 左边的主按钮，给创建订单的「添加」、改日期的「保存」用。
- `orderReschedulePreview.tsx`：
  - `RescheduleFooter` 去掉保存；
  - 新增 `RescheduleSaveButton`，两步红框和 `data-card-remove` 跟着走。
  - 调度台和改日期弹框都用它。
- `OrderPane.tsx`：创建订单的「添加」放到头上，底部只写已选日期；改日期的保存经 `reschedule.save` 放到头上。
- `CompanyPage.tsx`：订单弹框头上「关闭」左边放空位。
- `AiOrderCard.tsx`：「生成订单」放到头上。
- `LibraryActivityEditor.tsx`、`ActivityReview.tsx`、`ActivityPicker.tsx`：主按钮放到弹框头「关闭」/「取消」左边。
- CSS：`card-head-actions`、`card-save-slot`、`card-save`、`library-sheet-bar-actions`。
- 文档：FRONTEND_DESIGN 第 1 节加了这条规则。

## 验证

- `tsc -b` 通过，lint 没有新错误。
- 沙盒（桌面 1366×900、iPhone 13 模拟）逐个打开，检查「保存」在关闭按钮左边、同一行、紧挨着：
  - 调度台编辑订单、调度台改日期、司导卡片备注、创建订单（框选后）、添加车辆、公司信息订单弹框、公司信息改日期弹框、活动库添加活动，都是 true。
  - 调度台编辑订单时，「订单信息」那一行已经没有保存。
- 我的行程：订单信息编辑时保存在卡片头上，改了司导备注点保存，接口里已写入。
- 页面没有报错。
- AI 建单因为沙盒没有密钥，没能在页面上打开核对页；代码上是同一个头部布局。
