# 粗单填入行程明细、手机保持登录 2026-11-19

## 需求

1. 手机网页每次都要重新登录（11-18 提出）。
2. 粗单填入行程明细（11-18 定的规则）：
   - 在粗单上直接上传或粘贴行程明细，由 AI 识别；UI 和接口尽量复用 AI 建单；不和系统里已有的单合并，避免误操作。
   - 以新的细单为准；细单没填的保留粗单的数据。
   - 日期变了，司导和车辆同步挪动；有冲突就标红。
   - 司导也用这个流程；按订单号「领取订单」保留（用户 11-19 确认两个都保留）。

## 改动

### 1. 保持登录

- 原因：登录时没有设持久登录，`trailink.auth` 是会话 cookie（没有过期时间）。手机浏览器切到后台常被系统关掉，cookie 跟着没了。
- 修改：`AuthSession.SignInAsync` 传 `IsPersistent = true`。cookie 带 14 天过期时间，用着就自动续期（原来的滑动过期设置不变）。退出登录照常有效。
- 11-18 我还说过「每次发版所有人被登出」，并打算把 Data Protection 密钥存进数据库。这次 code review 时看到 `docs/ARCHITECTURE.md` 第 8 节记着生产上 api 的登录密钥已经有自己的数据卷，那条原因不成立。
  - 改了一版后撤回了：不新增表，没有数据库结构改动。
  - 如果你发现发版后大家确实都被登出，说明那个数据卷没挂对，到时再查。

### 2. 填入行程明细

后端：
- 新服务 `OrderItineraryFill`：
  - 第 N 天对第 N 天：细单按日期排序后的第 N 天接粗单的第 N 条行程日（同一个 id），挪到新日期，司导、派出人、车辆跟着走。
  - 细单更长：多出的天是新的空白日（未派）。细单更短：粗单末尾多出来的天删掉，删掉的天派过司导时提醒一句。
  - 冲突：挪过去后司导或车辆那天已有别的订单，**照样保留**（和改日期不同，改日期是改回未派）。日历上按平时的冲突标红，并返回提醒。
  - 真实订单（绑公司）上，司导自己那几天的「仅日期」占位单照常被覆盖，不算冲突，和派单、改日期一致。
  - 每天的内容：
    - 细单写了行程说明、住宿就用细单的，没写保留粗单的。
    - 细单这天写了活动就整天换成细单的；没写保留粗单的活动，时间跟着日期挪。
  - 整单：
    - 订单号、车型、南/北岛：细单写了才改；人数：大于 0 才改；起始日期取细单第一天。
    - 补充说明接在自己原来的备注后面，不覆盖、不重复接；司导不写。
    - 订单号（TL-…）、所属公司、调度分配、抢单等级、截图、别人的备注都不变。
  - 电子票、行程图和 AI 建单一样保存。写库失败时新文件全部删掉；被替换的旧电子票在写库成功后才删。
- 接口：
  - `POST /api/orders/{id}/itinerary-fill/preview`：对照，不写库。
  - `POST /api/orders/{id}/itinerary-fill`：写入。
  - 权限同改日期（`canReschedule`）。
- AI 识别 `order-draft` 新增 `orderId` 字段：带上时，能改这张单日期的人都能识别，司导在自己的「仅日期」单上也能用。`status` 多了 `fillEnabled`。
- `OrderImport` 拆出「加活动和电子票」「存行程图」两段，建单和填入共用；检查规则也共用。

前端：
- `AiOrderCard` 加了 `fill` 模式：
  - 标题「填入行程明细」，按钮「填入（n 天）」；
  - 点了先弹对照确认框：冲突的那天红底红字，新加的天写「新加的一天，未派」，删掉的天划掉并写原来派的司导；
  - 确认后写入，有冲突时用黄色提示写出来。
- 入口：
  - 调度台：编辑订单信息「行程日期」一行，「在日历上拖动改日期」右边多了「填入行程明细」。改日期中不显示；换了打开的订单就关掉。
  - 我的行程：点开某天的订单信息，「行程明细」一行。卡片盖住整页，不显示备注栏（司导没有调度备注）。
  - 司导「行程管理」里按订单号「领取订单」照旧保留。

## 发布

- 只有前端和后端代码改动，没有数据库结构改动。
- 要上线需要打新文件名的包。
- 上线后各人下一次登录起才是持久 cookie；之前登录的那一份还是会话 cookie，浏览器关掉后要再登录一次，之后就会一直保持。
