# 公司信息编辑订单偶发 500 排查 2026-11-10

## 问题

12:20 左右在生产环境的公司信息里编辑订单，连续出现几次 500 错误，过一会又能保存成功了。

## 已经查过的

- 保存只发一个请求：`PUT /api/orders/{id}`，同时写订单信息和自己的备注。不会同时发好几个请求互相冲突。
- 这个接口里没有会偶发出错的写法：
  - 订单表没有并发版本字段，不会因为同时保存出现并发异常；
  - 唯一索引只有订单号和每人一条备注，同一个人重复保存只会更新那条备注，不会插入第二条。
- 内容本身有问题时（例如南/北岛的值不对、车型太长）接口返回 400，不是 500。
- 所以「过一会就好了」更像是服务器当时的问题，不是数据问题。按可能性排：
  1. 刚好在发布：api 正在重建、重启，或者数据库刚加完列，api 还是旧的进程。e2-micro 只有 1GB 内存，编译 api 时内存很紧，旧的 api 可能连不上数据库或超时。
  2. 内存不够：之前的速度诊断里看到过服务器偶尔卡 4–7 秒，数据库连接超时也会变成 500。
  3. 其他程序错误：要看日志里的异常才能确定。
- 要看服务器日志才能确认是哪一种。我这里连不到服务器。

## 诊断脚本

`release/diagnose-500-20261110.sh`：

- 只读，不连接数据库、不改配置、不重启容器。
- 收集这些：
  - 各容器的启动时间、重启次数、是否被 OOM 杀过；
  - 内存和交换空间；
  - 发布留下的后端备份目录名（可以从名字看出发布时间）；
  - 过去 8 小时 api 日志里的每条 fail 和异常（带 UTC 时间戳）；
  - api 的启停记录、数据库连接相关的错误；
  - postgres 的 ERROR / FATAL；
  - Caddy 的 5xx。
- 结果写到 `~/trailink-500-20261110.txt`。
- 用假的 docker 日志演练过，fail 记录、异常、启动记录都能正确列出来。
