# 登录与角色权限

## 目标

薄登录：公司表 + 用户角色字段 + 调度员申请。公司看全部界面；司导搜公司申请；公司批准或移除调度员。不过度设计，不隔离订单租户。

## 对应模块

1. 现有模块：订单 / 司机 / 调度台 / 司导日历仍走原 Controller，本轮只加认证与角色入口。
2. 改动文件：`Company` / `User` / `DispatcherApplication`、`AuthSession`、`AuthController`、`CompaniesController`、`CompanyDeskController`、`Program.cs`、增量 Migration、`frontend` 登录/个人信息/公司信息、`AuthContext`、`App` 菜单过滤、权威文档。
3. 已有功能：原先无登录；角色不另开 RBAC 表。
4. 没有第二个事实来源：角色只读 `users.role`；申请只写 `dispatcher_applications`；派单仍写 `itinerary_days.driver_id`。
5. 新增实体：`companies`、`users`、`dispatcher_applications`。未改已应用的 `InitialCreate`。
6. 现有订单 / 行程 API 路径不变，仅要求登录 Cookie。

## 改动

- Cookie `trailink.auth`，HttpOnly，SameSite=Lax，14 天滑动。Cookie 只存身份；角色每次从库读，批准/移除下次 `me()` 即生效。
- 角色三种：`company` / `dispatcher` / `driver`。注册只开放司导、公司；调度员不能自助注册。
- 司导注册同步建 `drivers` 行；公司注册同步建 `companies` 行。
- 申请：一用户一条待审（`user_id` 唯一）。批准改角色并绑 `company_id`，删除申请；移除改回司导、清空 `company_id`，保留 `driver_id`。
- 前端：`/login`、`/me`、`/company`；菜单按角色过滤。司导日历绑定登录 `driverId`。
- 未做 JWT、刷新令牌、Identity、权限矩阵、微信登录、订单按公司隔离。

## 命令结果

- 增量 Migration `20261024005802_AddCompaniesAndUsers` 已应用到本地 PostgreSQL。
- `dotnet test`：21 通过（含 `AuthFlowTests`：无 Cookie 401、申请/批准/移除）。
- 测试以公司账号登录后再打现有 CRUD / 日历预览。

## 浏览器

- 注册公司 `firma` / `验证公司A`：进入 `/orders`，菜单含订单、司机、调度台、公司信息、个人信息。
- 注册司导 `drva` / `验证司导`：`/me` 仅「我的行程」「个人信息」，搜「验证公司A」并提交申请。
- 公司 `/company` 点「批准成为调度员」：申请消失，出现「移除」。
- `drva` 再登录 `role=dispatcher`，可打开 `/dispatcher` 调度台。
- 公司移除后 `drva` `role=driver`；访问 `/dispatcher` 被送到 `/driver/calendar`。

## 未做

- 无忘记密码、改密、邀请链接、多公司切换。
- 无 JWT / refresh / Identity / 权限表。
