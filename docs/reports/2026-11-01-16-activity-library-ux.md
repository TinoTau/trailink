# 活动库交互优化

## 目标

用户试用活动库后提出：

1. 公司信息页的活动库布局不合理：搜索框右边是「添加活动」，添加的活动全部铺在页面上。活动会越来越多，管理要放进单独的弹框。
2. 创建或编辑活动时，点保存应该关闭弹框。
3. 手机上滑动屏幕优先，拖动要长按；本身就是拖动按钮的地方（把手）按下立即拖，不在把手上才是滑动。
4. 日期详情添加活动时，选完的活动要能长按拖动排序，因为顺序可能临时改变。

## 改动

### 公司信息页

- `ActivityLibrarySection` 只剩一张入口卡片：标题、一句说明、「管理活动库」按钮。
- 新增 `LibraryManager` 管理弹框（底部弹出，高 86%）：搜索框；目的地筛选（全部 + 7 个常用目的地）；可滚动的活动列表；底部整行「添加活动」。
- 点活动或「添加活动」，在管理弹框上面打开编辑框。

### 编辑框（`LibraryActivityEditor`）

- 保存或添加成功后关闭编辑框，管理弹框刷新列表。删除成功也一样。
- 新建时可以先选最多 3 张图片（压缩后预览，可移除），添加时一起上传。原来要先保存才能加图片。
- 新建成功但图片没传完：编辑框留着，转成编辑这项活动，提示重新添加图片。
- 编辑已有活动时，图片仍是即时保存，不关闭编辑框。

### 拖动手感（`useHoldReorder`）

- 新增 `handleProps`：⋮⋮ 把手按下立即拖动，把手设 `touch-action: none`，不滚动页面。
- 其他位置：长按约 0.5 秒才拖，未满 0.5 秒手指一动就是滚动（原逻辑不变）。
- 修了一个拖动跳回的问题：手机上同一次移动会同时收到 `pointermove` 和 `touchmove`，页面还没重绘时第二次会把刚换过的两项又换回去，结果拖到顶部总差一格。现在同一项只换一次，手指回到被拖的那项上再重置。这个问题之前也存在于当日活动的长按排序。
- 当日详情的活动：⋮⋮ 把手接上 `handleProps`，加大了把手的按压范围。

### 活动选择框（`ActivityPicker`）

- 列表每行右侧有 ⋮⋮ 把手，长按或按住把手可调整常用顺序（仍保存到本人账户）。
- 新增「已选」区：按点选先后列出，可按把手或长按拖动调整这一次的顺序，× 移除。圆圈编号跟随「已选」的顺序。
- 确认后按「已选」的顺序加进这一天。
- 列表的排序规则不变：先本人顺序，其次评分。
