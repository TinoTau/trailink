# 抢单（第一版，不含收费和竞价）

## 需求

调度员把手头的单分出去，交给陌生司导：

- 订单分三个等级：调度自留（默认）、公司内部、面向所有人，决定给哪些司导看。被调度员隐藏的司导看不到自留单和公司内部单。
- 等级在调度台编辑订单里调，放在日期天数下方，样式和住宿位置那排按钮一样，三个互斥，不能都不选。
- 新增抢单界面：司导看到自己能接的单。接到内部单自动成为这张单调度员的司导；接到公开单同时成为调度员和公司的司导。

确认过的规则：

- 整单或拆单剩下的一段一起接，不能只接其中几天。
- 这些日期自己已有行程就不能接，由司导自己决定是否先取消原来的。
- 抢单前看行程信息和调度员姓名；联系方式、共用备注等接到后再看。
- 没绑公司的单只能调度自留，先绑公司才能改等级。

## 改动

### 数据库

- 迁移 `AddOrderShareLevel`：`orders.share_level`，整数，默认 0。只加一列，已有订单都是 0（调度自留）。没有新表。

### 后端

- `OrderRules.DispatcherId`：订单的调度员 = 公司分给的调度员，没有时是建单人。
- `PUT /api/orders/{id}/share-level`：只有这张单的调度员能改；没绑公司只能 0。订单响应新增 `shareLevel`、`canSetShareLevel`。解绑公司、换调度员、退回公司池时回到 0。
- `Services/OrderGrab` + `GrabController`：
  - `GET /api/grab`：按等级、隐藏关系、未派日期（且都不早于今天）列出能接的单，带上自己在这些日期已有的行程（冲突）。只给行程信息、公司名、调度员姓名、游客人数。
  - `POST /api/grab/{orderId}`：传入看到的待接日期；和当前未派日期不一致返回 409（被接走或改过）；有冲突 409；按订单行加锁，同时接只有先到的成功。成功后派出人记成调度员，并按等级写已批准的司导申请和公司成员。

### 前端

- 调度台订单卡片编辑里的三个等级按钮（`DispatcherCalendarCard` 的 `ShareLevelBar`），只给这张单的调度员显示；没绑公司时后两个置灰并提示。
- 抢单页 `/driver/grab`（`pages/grab/GrabPage.tsx`、`grab.css`）：「···」菜单进入；按等级筛选、刷新、说明；每张单一张卡片（日期范围、天数、等级标签、公司 · 调度 · 游客、拆单说明、每天的日期 / 住宿地浮雕字 / 活动和时间）；两步确认接单；冲突标红并给「去处理」。
- 我的行程支持 `?date=YYYY-MM-DD`：停在这一天并展开当日详情（接单后「去我的行程」用它）。
- 重新生成 OpenAPI 前端类型。

## 验证

- 后端测试 107 / 107 通过，新增 `GrabTests` 3 个：
  - 三个等级各自给谁看；隐藏后看不到自留和内部、仍看得到公开；只有调度员能改等级；没绑公司不能改；解绑后回到自留；列表不带共用备注。
  - 拆单只放出剩下的日期；冲突时列表标出、接单 409；只接几天 409；自己取消冲突那天后能接；晚到的人 409 且列表里消失；派出人是调度员；接到后出现在调度员和公司账户的司导名单里。
  - 公司内部单接到后成为调度员的司导；司导看列表时调度员加了一天，接单提示刷新。

## 补充（用户试用后的修改）

1. **隐藏就是拉黑**：被调度员隐藏的司导，看不到这位调度员放出的任何单，面向所有人的也看不到，也不能接（返回 404）；恢复后又能看到。原来只挡调度自留和公司内部。
2. **公司账户也能改等级**：订单所属公司的公司账户和这张单的调度员都能改（调度台、派给调度的编辑订单里都显示三个按钮）。原来只有调度员能改，所以公司账户看不到按钮。别的公司、司导仍是 403。
3. **抢单页 404**：本机的后端是 `dotnet run` 启动的，改了代码不会自动加载，旧后端没有 `/api/grab`，所以返回 404；本机开发库也还没有 `share_level` 这一列。`update-dev-db.cmd` 改为依次执行 `trailink-schema-20261101.sql` 和 `trailink-schema-20261102.sql`（都可以重复执行），执行完重启 `start-dev.cmd`。

测试：`GrabTests` 增加公司账户能改、别家公司和司导不能改、公开单对被隐藏的人不可见、恢复后可见、被隐藏的人接单 404。后端 107 / 107 通过。
