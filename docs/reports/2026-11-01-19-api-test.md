### 实测内容

用 5 个身份走完整流程：未登录、公司账户、调度员（司导申请后由公司批准）、司导（向调度员申请后批准）、无关的司导。

- **登录与资料**：注册（含重名、不能直接注册调度员）、登录、错误密码、登出后失效；改姓名 / 用户名 / 密码 / 联系方式 / 已分配颜色（色板外拒绝）；头像上传（格式不对拒绝）和读取。
- **公司与人员关系**：搜公司、申请成为调度员（重复申请、公司账户申请被拒）、公司批准后角色变为调度员；公司信息、公司头像、公司简称、调度员备注和隐藏（调度员不能写）；司导向调度员申请、批准、解除；司导名单范围（司导只看到自己）；司导档案增改删；头像和驾照只有名单里的上级能看。
- **驾照**：上传、列表、读取、替换、删除；上级只能看不能删；无关的人看不到。
- **订单**：公司建单自动绑本公司；游客人数为负拒绝；同一天重复建拒绝；整单分给调度员（只能本公司调度员，司导不能分）；各人备注互不可见，司导读不到备注；整单派司导、按天取消和派回；公司不能取消调度员派的日期；按司导、按日期查询；日期冲突时默认保存并返回提示，`failOnConflict` 时 409。
- **活动**：新建、修改、排序（缺项拒绝）、空内容和带时区的时间拒绝、活动不属于这一天时 404；电子票上传、读取、删除。
- **订单截图**：上传、列表、读取、删除。
- **车辆**：增改删、车牌重复拒绝、别人的车 404；照片最多 3 张（第 4 张 400）、替换、删除；整单绑车、全部已有车时 400、别人派的日期不能绑、只解除当天。
- **活动库**：目的地（常用、搜索、司导不能新建、同名返回已有）；活动增改删（司导、调度员 403，没有目的地或英文名忽略大小写重名时 400）；图片；评分（超范围 400、平均分和人数正确）；按住宿位置选择（评分排序、本人顺序在前、找不到目的地时为空）；从活动库加到当日（按传入顺序）；删库后行程里的文字保留。
- **删除与退回**：司导不能删订单；调度员删除是退回公司池（调度员和司导都清空）；公司删除后 404；公司不能移除自己。

### 已知问题（与契约不符，但属于已登记的待办）

无关的登录用户只要知道 ID，就能读到别人的订单详情、电子票和订单截图（都返回 200）。这就是 `DEVELOPMENT_PLAN.md` 第 5 节「按订单归属的数据权限」，用户已决定等抢单设计完再做，这次没有改。

### 测试脚本本身的修正

第一次跑有 3 处是脚本写错，不是接口问题：

- 隐藏 / 恢复调度员返回 204（无内容），脚本原来只认 200。
- 公司改订单时没带 `notes`，按契约这会清空本人备注，脚本随后误判「备注没分开」。改为带上后通过。
