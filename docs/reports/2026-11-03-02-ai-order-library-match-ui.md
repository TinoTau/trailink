# AI 建单：活动库匹配更准；核对页精简

## 需求

用户用真实 Claude Haiku 5.5 在本机试了 AI 建单，效果不错。两点改进：

- 和活动库匹配得更准（用户确认：只是匹配已有的，不往活动库新增）。
- 核对页保持全部展开，只精简字段。

## 改动

### 活动库匹配

- 提示词第 6 条：每项活动和酒店都先在库里找，中英文互译、简称全称、电子票英文商品名、酒店中文译名和英文原名都算对上；同名项目按目的地选。
- 新增 `LibraryMatcher`：模型没关联上的，后端按名字再找一遍（互相包含、忽略空格标点大小写；短名字要目的地对上；最高分并列不关联）。活动用当天住宿地和前一晚住宿地，酒店只用当天住宿地。
- 关联上的活动名统一改成库里的名字（和从活动库添加一致）。
- `LibraryItem` 改为保存中文名、英文名和目的地列表。

### 核对页

- 订单号、人数一行，备注一行，都不再单独占标题。
- 每天：勾选框 + 「11月20日 周五」（点开日期选择）+ 右侧「住 xx」；行程框随内容变高；没勾的天只占一行。
- 活动一行：名称（「酒店」「库」标签）、签到、开始、电子票、删除；去掉承办方输入框（值照样保存）；电子票下拉只在有 PDF 或已配票时出现。
- 时间改成 24 小时制文字框（1530 / 15:30 / 15.30 都行），修复英文系统下自带时间框把 20:00 显示成「08:00」的问题。
- 手机上活动换两行，删除按钮留在名称同一行。

## 验证

- `dotnet test`：全部通过（新增 `LibraryMatcherTests` 5 个用例：中英文和空格变体、酒店英文名、短名字靠目的地、泛称和并列不关联）。
- 前端 `tsc -b`、`npm run build` 通过。
- 沙盒界面（假 Claude 接口）：桌面和手机各走一遍；时间框输入 915 → 09:15、25:99 退回、10.40 → 10:40；生成的订单活动库关联和时间正确，无页面报错。

## 未做

- 不自动往活动库新增（用户确认不需要）。
- 数据库结构没有改动。
