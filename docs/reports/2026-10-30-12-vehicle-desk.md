# 调度台车辆管理

## 目标

在现有调度台订单区增加车辆标签。操作沿用订单区同一套控件：标签、图标、置顶、详情卡片、保存、照片上传和红框删除。触屏拖动前按住约 0.5 秒，鼠标按下即可拖。绑定只写 `itinerary_days.vehicle_id`。

## 改动

- 新增 `vehicles`、`vehicle_photos`，行程日增加 `vehicle_id`。迁移 `20261030091300_AddVehicles` 已写入本地库的 `__EFMigrationsHistory`。
- `VehiclesController` 管当前调度员的车和照片。`PUT /api/orders/{orderId}/days/{dayId}/vehicle` 把车绑到该司导在这张订单里由当前调度员分配的那些天。
- 调度台订单区增加「订单 / 车辆」。车辆下是「添加车辆 / 可用车辆 / 所有车辆」。图标、置顶、拖拽走现有 `beginPointer`。可用车辆删除只改 `available`，所有车辆删除才删数据。车辆标签下，司导日历里自己分配且已绑车的日期显示车牌。
- 派给调度没有车辆标签。排序和置顶在本机 `trailink.dispatcher.vehicleLayout`。
- 权威文档已把车辆从挂起和「不创建」里移出。

- `npx tsc -b --pretty false`（frontend）：通过。
- `dotnet test` 过滤 `VehicleTests`，输出改到临时目录：通过 1。覆盖调度员隔离、重复车牌、五天订单只绑定该司导负责的两天、第四张照片 400、移出可用、真删除后行程日 `vehicle_id` 清空。
- 本地 API 曾锁住 `Trailink.Api.dll`。已停掉旧进程并重新启动 `http://localhost:5168`。`192.168.68.56:5173/dispatcher` 原会话仍在。
- 浏览器：切到车辆后三个按钮替换订单按钮；添加车牌「验A0001」后出现图标和同一套详情；垃圾桶先变成红框「确认移出可用车辆」，再点后从可用车辆消失，仍在所有车辆；所有车辆里红框确认后列表为空。没有把车拖到真实订单上。没有上传照片。验证用的车已删除。
