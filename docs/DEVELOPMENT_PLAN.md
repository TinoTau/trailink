# Trailink V1 开发计划

版本：V1 MVP 第一阶段  
日期：2026-10-23

本计划只覆盖第一阶段可运行核心功能。未经批准不得扩大业务范围、创建收费 AWS 资源或进行生产部署。

---

## Phase 1 — 基础工程

任务：

- 创建 Git 项目结构
- 创建 ASP.NET Core Web API
- 创建 React + TypeScript 前端
- 配置 PostgreSQL
- 配置 EF Core
- 创建数据库迁移
- 配置 Docker Compose
- 建立本地开发环境

验收：

- 后端能够启动
- 前端能够启动
- 数据库能够连接
- Migration 能够执行
- Swagger / OpenAPI 能够访问

---

## Phase 2 — CRUD

任务：

- Drivers CRUD
- Orders CRUD
- Itinerary Days CRUD
- Order Files CRUD
- S3 文件存储接口

验收：

- 能创建、查询、修改和删除司机
- 能创建多日订单
- 能修改每日行程
- 能上传和查看原始订单附件

本地开发可使用 S3 兼容的本地测试存储或可替换的文件存储配置，不得要求开发者一开始就创建正式 AWS 资源。

---

## Phase 3 — 派单

任务：

- 整单派单
- 单日派单
- 修改司机
- 清空司机
- 简单日期冲突提示

验收：

- 一个三日订单可以全部分配给同一司机
- 可以将第三天修改为另一名司机
- 数据库直接更新 `driver_id`
- 不生成任何派单历史记录

---

## Phase 4 — 日历与部署准备

任务：

- 订单日历
- 司机日历筛选
- 手机端响应式适配
- 基础 API 测试
- Docker 构建
- AWS 部署配置和说明

验收：

- 可以按月份查看行程
- 可以筛选司机
- 可以点击日期查看行程详情
- 前后端可以通过 Docker 构建
- 提供 AWS 部署说明和预计资源成本

第一阶段不要求在未经批准的情况下直接部署收费 AWS 资源。

---

## 质量要求

必须：

- 保持代码简单易读
- 使用清晰的英文命名
- API DTO 与数据库实体适度分离
- 使用 EF Core Migrations
- 处理基本输入错误
- 使用异步数据库访问
- 避免 SQL 注入
- 保护数据库连接字符串和 AWS 密钥
- 不将真实密钥提交到 Git
- 为核心 CRUD、派单和日历查询编写基础自动化测试
- 提供 README 启动说明

不要求：

- 100% 测试覆盖率
- 复杂测试基础设施
- 多层接口抽象
- 高并发性能优化
- 分布式架构
- 自动化运维平台

---

## 当前进度

已完成：

- 目标框架 net10.0，SDK 10.0.402（`global.json` 锁定）
- 本地 Docker PostgreSQL 16
- 司机 CRUD
- 订单 / 每日行程 / 活动项目 CRUD
- 整单与按天派单（只写 `itinerary_days.driver_id`）
- 订单列表与订单编辑界面
- 司机端连续滚动日历；公司、调度员、司导登录后都看本人行程
- 司机日历与调度台共用订单 / 司导列表；领取、框选建稿、取消只写 `itinerary_days.driver_id`
- 调度台：创建订单与司导同一套框选建单、筛选项为未分配/所有订单、已分配颜色仅在所有订单、卡片日历标出当天、两卡同时打开时订单日历按月带动司导日历、订单卡可删除、订单信息保存后回日历、当日行程独立卡片、整单/按天拖拽派单、从司导卡片拖一天到订单区取消（拆单取消当天、未拆单取消整单）、司导置顶在图标上、移除在卡片备注旁（localStorage），冲突拒绝写入
- Cookie 登录与三类角色；公司表；申请成为调度员由公司批准；申请成为司导由调度员批准，写入 `company_members`
- 本地演示数据：`dotnet run -- --seed-demo`（密码均为 `Passw0rd!`）
- 统一本地文件存储：二维码、头像、电子票、订单截图，根目录 `App_Data/files/`

未完成：

- 按公司隔离订单
- 收费 AWS 资源与生产部署
