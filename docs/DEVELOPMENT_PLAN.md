# Trailink V1 开发计划

版本：V1 MVP 第一阶段  
日期：2026-10-23

本计划只覆盖第一阶段可运行核心功能。未经批准不得扩大业务范围、创建收费 AWS 资源或进行生产部署。

---

## Phase 1 — 基础工程

任务：

- 创建 Git 项目结构
- 创建 ASP.NET Core Web API
- 创建 React + TypeScript 前端
- 配置 PostgreSQL
- 配置 EF Core
- 创建数据库迁移
- 配置 Docker Compose
- 建立本地开发环境

验收：

- 后端能够启动
- 前端能够启动
- 数据库能够连接
- Migration 能够执行
- Swagger / OpenAPI 能够访问
- `/openapi/v1.json` 为前端 API transport types 的唯一来源，`npm run api:types` 生成 `frontend/src/api/generated/`

---

## Phase 2 — CRUD

任务：

- Drivers CRUD
- Orders CRUD
- Itinerary Days CRUD
- Order Files CRUD
- S3 文件存储接口

验收：

- 能创建、查询、修改和删除司机
- 能创建多日订单
- 能修改每日行程
- 能上传和查看原始订单附件

本地开发可使用 S3 兼容的本地测试存储或可替换的文件存储配置，不得要求开发者一开始就创建正式 AWS 资源。

---

## Phase 3 — 派单

任务：

- 整单派单
- 单日派单
- 修改司机
- 清空司机
- 简单日期冲突提示

验收：

- 一个三日订单可以全部分配给同一司机
- 可以将第三天修改为另一名司机
- 数据库直接更新 `driver_id`
- 不生成任何派单历史记录

---

## Phase 4 — 日历与部署准备

任务：

- 订单日历
- 司机日历筛选
- 手机端响应式适配
- 基础 API 测试
- Docker 构建
- AWS 部署配置和说明

验收：

- 可以按月份查看行程
- 可以筛选司机
- 可以点击日期查看行程详情
- 前后端可以通过 Docker 构建
- 提供 AWS 部署说明和预计资源成本

第一阶段不要求在未经批准的情况下直接部署收费 AWS 资源。

---

## 质量要求

必须：

- 保持代码简单易读
- 使用清晰的英文命名
- API DTO 与数据库实体适度分离；前端不手写重复 DTO，页面权限与菜单只读统一导航配置
- 使用 EF Core Migrations
- 处理基本输入错误
- 使用异步数据库访问
- 避免 SQL 注入
- 保护数据库连接字符串和 AWS 密钥
- 不将真实密钥提交到 Git
- 为核心 CRUD、派单和日历查询编写基础自动化测试
- 提供 README 启动说明

不要求：

- 100% 测试覆盖率
- 复杂测试基础设施
- 多层接口抽象
- 高并发性能优化
- 分布式架构
- 自动化运维平台

---

## 当前进度

已完成：

- 目标框架 net10.0，SDK 10.0.402（`global.json` 锁定）
- 本地 Docker PostgreSQL 16
- 司机 CRUD
- 订单 / 每日行程 / 活动项目 CRUD
- 整单与按天派单（只写 `itinerary_days.driver_id`）
- 调度台车辆：登录用户各自的 `vehicles` / `vehicle_photos`，公司账户同样可管；点图标先开车辆日历，编辑才进详情；绑定只写 `itinerary_days.vehicle_id`，我的行程点开日期时在住宿位置按钮下显示这辆车的车牌、型号和共用备注，未绑定不显示；整单和拆单都只填还没有车的日期，都有车则不写；车辆管理时司导日历的拖动只解除车辆；车辆日历默认居中今天这一行，司导日历滑动带动车辆日历，已绑定日期写司导名字，点日期对跳；同一天两单用同一辆车时标红，按订单冲突的方式解除当天绑定；照片在页面里压成 jpg 后再上传，详情并排三张小图，点小图时详情撑到页面底部再看大图，左右滑动换一张，大图按横向比例固定展示，竖图也缩到这个高度；下方横杠一样长，当前这张更深，点详情框里照片和按钮以外的空白处关闭大图，详情还在并缩回打开时的高度；删除照片先套红框再点一次；拉长横条固定在详情框底部，打开时至少高到停用按钮下方，离框底再留 8 像素，详情框可向下超出车辆区并盖住司导区；详情里可用时只显示停用，先套红框再点一次才写入 `available`；停用时只显示可用，点一下就恢复。点弹框外没有按钮的空白处关闭，与订单详情同一套；垃圾桶删除车辆；订单和车辆分两个请求；订单区用同一行标签切换，下面是当前页的操作按钮；图标拖拽与订单相同（触屏先按住约 0.5 秒，鼠标按下即可拖）；置顶记在本机 `trailink.dispatcher.vehicleLayout`，未置顶的按车牌字母顺序，只在置顶组内拖动排序
- 订单在调度台与本人行程里编辑，不另开 `/orders` 列表页
- 司机端连续滚动日历；公司、调度员、司导登录后都看本人行程，已结束的单也留在日历上
- 司机日历与调度台共用订单 / 司导列表；有行程日期框与调度台司导日历共用 `CalendarDayCaption` 展示派出人，我的行程在已绑公司时连上公司名，过长则用本人的公司缩写；点日期展开的订单信息与调度台订单卡同一套 `OrderInfoFields` / `updateOrderInfo`，备注分 `order_notes`（调度员各人一条）/ `orders.driver_notes` / `orders.shared_notes`（公司、调度员、司导共用，显示在各自备注上方；没有公司订单号时，订单名称用它）；领取、框选建稿、取消只写 `itinerary_days.driver_id`；领取已绑公司真实订单时覆盖并删除本人占位单
- 切换到调度台、派给调度、我的行程、公司信息或个人信息，以及从其他窗口回到当前页时，重新读取该页数据；未保存的输入保留
- 调度台：创建订单与司导同一套框选建单，一次最多三个月，拖到边缘时日历跟着滚动，创建、订单、司导和车辆日历都从半年前画到半年后、筛选项为未分配/所有订单（未分配含过期仍有空日期的单和同一司导日期重叠的冲突单；所有订单不含已派完且已结束的历史单）、已分配颜色仅在所有订单且按用户写入 `users.assigned_color`、卡片日历标出当天、两卡同时打开时订单日历按月带动司导日历、订单卡已绑公司时调度员退回公司池、未绑公司或公司账户才真删、订单信息保存后回日历、当日行程独立卡片、整单/按天拖拽派单（触屏拖动订单和人员需先按住约 0.5 秒，否则滑动对应区域；详情日历里没有订单的日期直接拖动是滑动，有订单的日期直接拖动是整单，按住约 0.5 秒再拖是当天。鼠标按下即可拖，拖某一天仍只改那天）、点开司导时日历包含这位司导的全部行程（含已完成和进行中已过日期），打开时，订单日历未打开则滚到今天；订单日历已经打开时，订单日历保持原位，司导日历滚到订单日历当前的日期位置。着色与我的行程相同：早于今天用已完成色，今天和之后用未完成色，不限本公司，只有自己派出的日期与我的行程日期格同一套文字，别人派出的日期不能拖动，点一下只提示，触屏仍可滑动；整单里有别人派出的日期时整单也不能被拖起；从司导卡片拖回订单区：鼠标按是否拆单决定取消当天或整单，触屏直接拖取消整单，按住约 0.5 秒再拖只取消当天（仅自己分配的单；我的行程取消本人行程不看分配人）、司导图标圆圈显示其上传的头像，没有头像则显示姓名第一个字，下方优先显示当前调度员自己的备注（互不可见）、无备注才显示姓名；派给调度的调度员圆圈同样显示上传的头像，置顶在图标上（localStorage），隐藏写 `driver_notes.hidden`，移除在卡片备注旁，重叠日期仍写入并由日历标红、按天拆单移除（已绑公司的真实订单可覆盖并删除司导自建未绑公司占位单）；公司信息页：公司账户只看已派完且已结束的历史单；司导看自己当前接的单，调度员看自己当前接的和分配的单，已结束和尚未结束都在内，分配变化后不再显示
- 公司派给调度：`orders.assigned_dispatcher_user_id` + `PUT /api/orders/{id}/dispatcher`，页面复用 `/company/assign` 的调度台，只整单、同时只一位调度员；点调度员是订单池（未完成 / 已完成），可以排序、置顶和隐藏；隐藏写 `dispatcher_notes.hidden`；解除绑定走现有删除成员，不能解除公司账户自己，未完成订单退回公司池；点订单日历标司导；公司给调度员的备注写 `dispatcher_notes`
- Cookie 登录与三类角色；公司表；申请成为调度员由公司批准，批准前公司名单和派给调度都看不到；申请成为司导由该调度员批准，批准前他的调度台看不到，同公司其他调度员也不共享；批准后写入 `company_members`，并保留 `driver_applications.approved_at`；调度员可删除自己这一行来解除绑定；未完成订单里分给这位司导的日期按天收回，已结束的行程保留。第一次点垃圾桶只给垃圾桶套上红框，再点一次才解除，不弹框；公司账户或该公司调度员把公司订单派给有账号的司导时，若还不是成员则写入 `company_members.role=driver`，这不进入公司账户的调度台；公司调度台只看向本公司账户申请并已批准的 `driver_applications`，其中包含注册时自动批准的自指行，旧账号在登录或 `me` 时补上，不能解除自己的司导身份；批准前不显示别人，也没有隐藏记录；公司信息页只有公司账户能看到批准/移除调度员
- 个人信息可改自己的 `users.name`（`PUT /api/auth/name`）、联系方式（`PUT /api/auth/contact`，写 `users.contact`）、登录用户名（`PUT /api/auth/username`）和登录密码（`PUT /api/auth/password`，须验证当前密码；页面用明文输入当前密码和新密码）；有本人 `driver_id` 时同步 `drivers.name`，调度台司导卡读 `GET /api/drivers` 时优先显示账号姓名。有司导身份时，个人信息上传驾照正反面，压缩放在后台，正在处理的那一格转圈，写入 `driver_license_photos`，调度台编辑已批准司导的备注时看到这两张图。调度台司导详情、公司信息的待批准申请、个人信息的司导申请，以及我的行程点开日期后公司订单号下的调度员姓名旁，都读 `users.contact`
- 本地演示数据：`dotnet run -- --seed-demo`（密码均为 `Passw0rd!`）
- 清空业务表：`dotnet run -- --wipe-data`（含 `driver_notes`，不写入演示数据）
- 只清空订单、行程、活动和订单附件记录：`dotnet run -- --wipe-orders`，用户和公司保留
- 统一本地文件存储：公司头像、用户头像、电子票、订单截图，根目录 `App_Data/files/`。订单最后一天起满 7 天后删除电子票和订单截图
- 公司建单绑定本公司；调度员和司导建单都不默认绑所属公司，即使只属于一家；调度员须搜索并点选后立即绑定或改绑 `orders.company_id`；公司 `GET /api/orders` 只看绑到自己的单
